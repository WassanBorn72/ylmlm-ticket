# 開発者向けガイド

[利用者向けREADME](../README.md) / [リリース・署名手順](RELEASING.md) / [Android試用版](TRYING.md) / [iPhoneへの個人用インストール](IOS.md)

Expo / React NativeによるiPhone・Androidアプリです。チケット情報は端末から直接取得し、APIサーバー・定期取得ワーカー・バックグラウンド通知は使用しません。ユーザー登録やFirebase、EASプロジェクトIDの設定は不要です。

アプリ名は「モ！のチケット帳（非公式）」です。正式版のAndroid Application IDとiOS Bundle IDは `jp.ylmlm.unofficial.ticket`、試用版は `jp.ylmlm.unofficial.ticket.preview` です。Expo slugとURLスキームは `ylmlm-unofficial-ticket` です。識別子とバージョンの詳細は [配布手順](RELEASING.md#アプリの識別子) を参照してください。

## 情報取得・保存・新着判定の仕組み

- 取得対象は TicketDive・LivePocket・TIGET・イープラスの 4 サイトです。Buzzチケ・ローチケは現在の取得対象から外しています。
- 取得に成功したサイトの最新の一覧で置き換え、掲載から消えた公演・購入先を除去します。過去公演は日本時間の日付で非表示にします。完売でも公演ページが一覧に掲載されていれば表示します。
- 取得に失敗したサイトの前回情報は消さず、「前回取得」と明示します。その場合は現在の掲載を確認できていないので、取得状況と購入先を確認してください。途中まで取得できた場合もエラーを表示します。
- 初回取得は新着にせず、次に開いたとき／更新したときに初めて見つかった公演を `NEW` と新着タブに表示します。価格変更、同じ公演の別サイト掲載、再掲載は新着にしません。
- 前回情報・公演 ID・新着の既読状態は AsyncStorage で端末内にだけ保存します。新着の基準はサイトごとの初回成功まで確定せず、初回の部分失敗による誤判定を抑えます。アプリの再インストールや保存データ削除で基準はリセットされます。
- 公演カードと詳細のハートでお気に入りを登録・解除できます。お気に入りタブには掲載中の公演だけを表示します。登録は再起動後も保持し、端末間の同期は行いません。アプリの削除・データ消去で登録も失われます。
- トップは検索と一覧から始め、紹介枠は表示しません。「日付で絞り込む」ボタンからカレンダーを開き、開催日を選べます。公演のある日には印を付け、前月・翌月は矢印で移動します。選択後は日付の横の「解除」で戻せます。検索・新着・お気に入りと組み合わせて絞り込めます。
- 公演名・会場の検索、開催日による絞り込み、日付順の変更、公演詳細と購入ページへのリンクがあります。
- 一覧と詳細の会場名をタップすると、Androidでは地図アプリ、iPhoneではAppleマップを開きます。住所があれば会場名と一緒に検索し、住所未掲載なら会場名で検索します。地図アプリを開けない場合はGoogleマップのWeb検索を開きます。位置情報の権限や地図APIの料金は不要です。
- 不明な料金は「購入先で確認」、時間は「未掲載」と表示します。券種の条件・ドリンク代や、ページ内の時間の食い違いも表示します。

## 検証記録と制約

現在は端末直接取得方式で、v0.5.0では53件のテスト、スマホ幅での画面操作、Web / iOS / Android の JavaScript バンドル生成を確認しました。2026年10月11日（日本時間）に、アプリと同じ取得コードを Node.js から実行して重複統合後 **11 公演**を取得しました。

| サイト | URL | 確認結果 |
| --- | --- | --- |
| TicketDive | https://ticketdive.com/ | 検索から 6 公演の会場・時間・券種別料金を取得 |
| LivePocket | https://livepocket.jp/ | 検索から 4 公演。旧 `t.livepocket.jp` は使用しません |
| TIGET | https://tiget.net/ | 1 公演、前売／当日券を含む 8 券種を取得 |
| イープラス | https://eplus.jp/ | 1 公演の会場・時間を取得。公開ページに料金がなく「購入先で確認」と表示 |

LivePocket／イープラスの同じ YOIMACHI 公演は購入先をまとめています。件数は確認時点の値です。複数日開催、サイト側の形式変更には追加検証が必要です。未対応ページやアクセス確認画面を、掲載ゼロとして扱いません。

**実機からの接続は未検証です。** 各サイトが端末の回線やアクセス方法により取得を拒否する可能性があります。Node.js での取得成功や JavaScript バンドル生成は、実機での成功を保証しません。Web 版はブラウザーの CORS 制限により直接取得できないサイトがあります。制限回避用の公開プロキシやサーバーへの迂回は実装していません。

## 開発を始める

Androidスマホだけで試す場合は、[試用版APKのインストール手順](TRYING.md) を参照してください。正式リリースとは別の試用版です。

Node.js 24 以降を使用します。クラウドの作業ディレクトリは `/workspace/ylmlm-ticket` です。

```sh
npm ci
npm start
```

Expo Go またはネイティブ開発ビルドで確認できます。API URL、EAS プロジェクト ID、Firebase、通知資格情報の設定は不要です。以前の `EXPO_PUBLIC_API_URL` は読み取りません。

Android SDK がある環境では `npm run android`、macOS / Xcode がある環境では `npm run ios` でネイティブ開発ビルドを作成できます。Expo Go や開発ビルドは正式配布物とは異なります。

画面の開発用 Web 版：

```sh
EXPO_UNSTABLE_HEADLESS=1 EXPO_OFFLINE=1 EXPO_NO_TELEMETRY=1 npm run web -- --port 8081 --max-workers 2
```

クラウドでExpoのホームディレクトリへ書き込めない場合は、Expoコマンドの前に `__UNSAFE_EXPO_HOME_DIRECTORY=/tmp/yuru-expo-state` を付けます。依存関係のインストールは `npm ci --cache /tmp/ylmlm-npm-cache` を利用できます。

`EXPO_OFFLINE` は Expo CLI のオンライン確認を止める指定です。アプリのチケットサイトへの通信を止める設定ではありません。Web の見た目・動作は下記のページ抜粋を使うテストで検証し、取得可否は実機で確認します。

## 検証

```sh
npm run typecheck
npm test
npm run test:live
EXPO_OFFLINE=1 EXPO_NO_TELEMETRY=1 npx expo export --platform all --max-workers 2
```

- `npm test`：サイト別抽出、端末内の新着・既読、掲載終了、部分失敗、通信中断などのテストです。外部サイトには接続しません。
- `npm run test:live`：アプリと同じ取得コードで実サイトへ 1 回だけ接続します。ブラウザーや API サーバーは不要です。取得元ごとの状態と件数を表示し、失敗があれば終了コード 1 になります。
- `expo export`：Web / iOS / Android 用の JavaScript バンドルを生成します。APK / IPA のビルドや実機検証ではありません。

Web の操作テストは、上のバンドル生成後に別ターミナルで `python3 -m http.server 4173 --directory dist` を起動して実行します。

```sh
npx playwright install chromium
WEB_TEST_URL=http://127.0.0.1:4173 npm run test:web
```

このクラウドでは `CI=1 CHROMIUM_PATH=/usr/bin/chromium WEB_TEST_URL=http://127.0.0.1:4173 npm run test:web` を利用できます。チケットサイトへの通信だけを保存したページ抜粋に置き換え、実際の取得・抽出・保存処理を通します。検索・開催日フィルター・詳細・会場名と住所を含む地図検索リンク・重複統合・新着／既読とお気に入りの再起動後の保持・登録／解除・掲載終了・HTTP 403／オフライン・時間経過で自動巡回しないことを確認します。これは実サイトや実機での接続検証とは別です。

## GitHub Releases での正式配布

配布物と手順は [リリース・署名手順](RELEASING.md) を参照してください。

| OS | GitHub での配布方針 |
| --- | --- |
| Android | 自分のリリース鍵で署名した APK と SHA-256 チェックサムを GitHub Releases に添付。ダウンロードしてインストール可能 |
| iPhone | ソースとビルド手順を公開。macOS / Xcode で利用者自身の端末向けに署名してインストール。IPA の一般向け無条件配布はできません |

GitHub に置く場合でも iPhone の署名・プロビジョニング制約は残ります。無料の Apple ID による個人用インストールには期限があり、通常 7 日で再署名が必要です。有料登録での Ad Hoc 配布も登録済み端末に限られ、Android の APK のような一般配布にはなりません。

`.github/workflows/ci.yml` でテストと各 OS のバンドル生成を実行します。`android-release.yml` はバージョンタグから署名付き APK を作成し、GitHub Release の**下書き**に添付する手順です。正式な署名鍵を登録し、Android APKをGitHub Releasesで配布します。Android / iPhoneの実機検証結果はまだ記録されていません。

専用サーバーの運用費は不要です。GitHub Actions はリポジトリの公開範囲・プラン・使用量による制限があります。Android の GitHub 配布にはストア登録料が不要です。iPhone の個人用ビルドには macOS / Xcode が必要です。

## コードの構成

- `assets/app-icon.png`：アプリ内左上の文字なしアイコン。
- `assets/launcher-icon.png`：アプリ名と「非公式」を入れたホーム画面用アイコン。Androidのアダプティブアイコンにも使用します。
- `App.tsx`：一覧・新着・お気に入り・取得状況・詳細。起動／復帰／手動更新以外の巡回なし。
- `src/DateFilter.tsx` / `calendar.mjs`：日付選択カレンダー、公演日の印、月の移動。
- `src/tickets/sources.json`：検索ページ、アーティスト一覧、許可ホストと抽出設定。
- `src/tickets/collector.mjs`：端末互換の `fetch`、15 秒の通信制限、掲載一覧とページ送りの取得。
- `src/tickets/adapters.mjs` / `extract.mjs`：サイト別 HTML・JSON-LD の抽出、安定した公演 ID の生成。
- `src/tickets/state.mjs`：端末内スナップショット、重複統合、掲載終了・新着・既読の判定。
- `tests/fixtures`：公開ページから抜粋した検証用 HTML。ログイン情報・Cookie は含みません。

旧バックエンド、定期取得ワーカー、端末通知登録と Expo Push、サンプル公演へのフォールバックは削除しました。各サイトの利用条件を確認して取得頻度を抑え、構造が変わった際は抽出処理と検証用抜粋を更新します。


## 公式告知による詳細の補足（v0.3.0）

`src/tickets/official.mjs` で公式サイト `https://ylmlm.jp/` に現在表示されるカレンダーのHTML本文を取得します。サイト内で参照される公式告知に出演時間・特典会時間があれば抽出し、本文からイベント固有の注意事項・参加条件・券種別特典などを抽出し、その他補足として箇条書きで表示します。タイトル・出演者一覧・料金・開場／開演・購入案内などの重複情報と、既知の共通案内は省きます。未知の注意事項は注意事項欄から保守的に残し、原文を言い換えて条件を捏造しません。本文は内部キャッシュに保持するため、従来のキャッシュからも同じ抽出を適用できます。購入先URL（t-dv.comを含む）、開催日、公演名・会場を照合し、複数部など照合先が曖昧な告知は付与しません。公式告知だけで公演を一覧に追加しません。

取得は起動・復帰・手動更新時のみで、公式サイトへ1回接続します。追加のサーバーや認証情報は不要です。失敗時は前回の公式情報と確認日時を保持し、「前回取得」と表示します。チケット情報の取得とは独立して扱い、詳細補足によって新着やお気に入りのIDを変更しません。公式キャッシュは既存の端末保存データに追加し、旧形式も読み込めます。

XのプロフィールページはJavaScriptで投稿を読み込むため、今回の調査ではHTML本文から安定して投稿内容を取得できませんでした。Xへの直接接続、画像内タイムテーブルのOCR、カレンダーの別月への追加巡回は実装していません。公式サイトの本文に反映された告知を利用します。

公式カレンダーの公開HTML抜粋を `tests/fixtures/official-calendar.html` に保存し、抽出、日付・URL照合、曖昧な複数部の除外、失敗時の保持、復旧時の削除、再起動後の復元をテストします。今回の実サイト検証では11公演のうち9公演に公式告知を照合しました。件数は確認時点の値です。

## 公式リンク

トップのチケット一覧に公式サイトと公式Xへの共通リンクを表示します。詳細は購入先を補足より上に配置し、公式プロフィールやカレンダーへの重複リンクは表示しません。照合できた公式カレンダー告知の中に `x.com/ylmlm_official/status/…` または `twitter.com/ylmlm_official/status/…` があれば、公式アカウントのHTTPS投稿URLだけを保持し、同じ公演に投稿リンクを付与します。追跡クエリは除去し、他アカウントや外部ホストは採用しません。投稿URLがなければ公演別リンクを推測・生成せず、詳細には投稿リンクを表示しません。公式プロフィールはトップページの共通リンクから開けます。XへのAPIリクエスト・投稿本文の追加取得・有料サービスは使用しません。

## 個人・ユニット出演

`sources.json` の `targets` に6メンバーと4ユニットを定義します。TicketDive・LivePocket・TIGETはグループ、ユニット、所属を含めた個人名で検索し、各検索につき最大5ページ、各サイトにつき最大50公演候補を巡回します。同じ公演URLは一度だけ取得します。短い個人名の本文部分一致だけでは取り込みません。

公式カレンダーの告知タイトルから対象を確認できる場合は、掲載された購入先URLと開催日を裏付けとして所属表記がない公演も取得します。イープラスは既存グループ一覧と公式告知の個別公演URLが対象で、個人・ユニットの専用アーティスト一覧は未登録です。検索の網羅性にはこの制約があります。公式サイトを先に取得し、失敗時は前回の告知を照合に使用します。通信中断はその後のチケット巡回も止めます。

イベントの既存IDは維持し、出演対象の追加で新着やお気に入りを再作成しません。複数サイトの公演統合では出演対象も統合し、出演者名を検索欄の対象に追加します。

今回の確認では、53件のテストと、個人名の誤検出防止・公式告知の裏付け・独立検索の巡回を検証しました。実サイトでは4サイトとも取得に成功し、12公演のうち「なにぬねるん」の「LIGHTのすゝめ」を新たに取得しました。件数は確認時点の値です。

### 出演者フィルターと外部コラボ（v0.6.0以降）

`PerformerFilter.tsx` で単一の出演者を選択する。検索・開催日・新着・お気に入りと AND 条件で絞り込む。タブ切り替えで解除する。個人を選んでもユニット出演を自動展開しない。古いキャッシュに出演者情報がない場合はグループとして扱い、更新時に照合した出演者を反映する。

取得対象の `kind: collaboration` は内部の区分として保持する。画面の出演者選択では `unit` とまとめて「ユニット」に表示し、一覧・詳細はどちらも名前のみを表示する。桃組暴想族と Babywiper or Gangster を追加し、後者は TicketDive に存在する Gangstar 表記も同じ対象に照合する。利用者から提供された情報に基づき `participantIds` に桃組暴想族＝member-2（ねるん）、Babywiper or Gangster＝member-4（めあり）を設定する。参加メンバー情報は内部に保持し、一覧・詳細・出演者選択では「○○参加」を表示しない。この対応表は個人フィルターの条件には使わず、公演ごとの出演確認を代替しない。活動継続は推測しない。TicketDive・LivePocket・TIGET の検索を追加し、イープラスは従来の公式告知リンクによる補完を使う。
